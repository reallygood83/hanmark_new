- 관련 문서: R-018(번들·결정성), R-019(출력 언어), R-020(불러오기 옵션 화이트리스트·보기 화면), 2.7.0 통합 업데이트 계획(W7·W8)

## 1. 조사 질문

1. 서로 다른 형식(HWP·HWPX·PDF·DOCX·XLSX)의 두 판을 비교해, 그대로 제출해도 될 만큼 정확한 신구대조표 노트를 오프라인·결정적으로 만들 수 있는가?
2. HWPX 양식의 칸을 노트 속성으로 채우고, 원본 양식을 건드리지 않은 채 같은 입력이면 같은 파일을 저장할 수 있는가?

## 2. 범위

### 포함

- 두 문서 비교(볼트 파일·외부 파일, 형식 혼합), 블록 정렬, 낱말 단위 변경 표시, 대조표 노트 형식과 파일 이름
- 양식 입력 노트 만들기(누름틀·라벨 칸·머리행 표), 채워 저장, 양식 변경 감지, 내장 표준 기안문 2종, 개인정보 안내

### 제외

- HWP(바이너리) 양식 채우기, PDF 양식, OCR, 도장 날인, 개인정보 가리기, 비교 결과를 원본에 되돌려 쓰기

## 4. 확인된 사실

- Kordoc 비교는 블록 정렬에서 "완전히 같음"과 "비슷함"에 같은 점수를 준다. 조문 하나를 넣으면 뒤따르는 조문이 모두 한 칸씩 밀려 "수정"으로 나올 수 있다.
- Kordoc 양식 읽기는 표마다 라벨–값 쌍을 먼저 찾고, 머리행 표의 빈 행은 필드로 내놓지 않는다. 채우기 엔진은 머리행 표를 올바르게 채운다.
- 한국어 신구조문대비표의 관례 표시는 밑줄이지만, Kordoc 4.15.7 HWPX 생성기는 밑줄을 버린다. 굵게는 HWPX로 내보내고 다시 읽어도 남는다(왕복 테스트).

## 5. 결정(구현됨)

1. **정렬 보완**(`documentDiff.ts`): 두 문서의 블록을 공백을 정규화한 내용 키(종류·제목 수준·글·표 셀·하위 블록)로 비교해, 완전히 같은 블록을 LCS로 먼저 고정한다. 고정점 사이의 블록만 Kordoc `diffBlocks`에 맡겨 수정·추가·삭제를 정한다. 블록 쌍이 1,600만을 넘으면 메모리 한도로 Kordoc 정렬만 쓴다.
2. **읽기**: 두 문서를 차례로(동시에 하지 않음) `parse`한다. 옵션은 불러오기 화이트리스트 타입(`{ images: false }`)이다. 실패하면 파일 이름과 오류 안내 카탈로그 제목으로 알린다.
3. **대조표 노트**(`compareNote.ts`): 제목 → 요약 콜아웃(추가·삭제·수정·동일 수) → `| 구분 | 현행 | 개정(안) |` 표 → "표 변경 내용" 목록(표 n · r행 c열: 이전 → 이후). 동일 블록은 기본으로 숨기고 선택하면 보인다. 표는 칸에 "[표 n · r행 c열]"로 요약한다. 제목·라벨·파일 이름은 출력 언어(R-019)를 따르며, 파일 이름은 `신구대조표 - A → B`에서 Obsidian이 거부하는 문자를 `_`로 바꾼다.
4. **낱말 표시**(`wordDiff.ts`): 글자·숫자 묶음, 공백, 문장부호 하나를 토큰으로 LCS를 구한다. 바뀐 토큰이 있으면 그 **어절 전체**를 표시해 강조가 늘 어절 경계에서 열리고 닫히게 한다(모든 Markdown 렌더러에서 동작, 관례와도 맞음). 이웃한 바뀐 어절은 한 구절로 묶는다. 강조는 줄바꿈을 넘지 않으며, 표 칸 안의 줄은 `<br>`로 잇는다. 기본 표시는 굵게, 선택으로 `==형광==`(Obsidian 화면용)이다.
5. **글 보호**: 문서 글 속 Markdown·Obsidian 문법 문자(`\`, `` ` ``, `*`, `_`, `~`, `|`, `$`, 태그 앞 `<`, `[[`·`[^`, `==`, `%%`, 줄머리·공백 뒤 `#`)는 Kordoc 불러오기와 같은 방식으로 이스케이프한다. Kordoc이 담은 `\$`는 풀었다가 다시 이스케이프해 이중 이스케이프를 막는다.
6. **양식 입력 노트**(`formFill.ts`): 필드는 누름틀(이름·안내문) → 블록 순서대로 라벨 칸·문단 속 "라벨: ____" → 머리행 표의 빈 열. 이름을 정규화해 겹치는 필드는 한 번만 넣는다. 머리행 표는 머리행이 모두 짧은 라벨이고 아래 행에 빈 열이 있을 때로 판정한다. 채워진 열이 번호뿐이거나 빈 열이 둘 이상이면 머리행 표로, 행 이름 열 하나와 빈 열 하나뿐이면 라벨–값 표로 본다. 빈 행이 둘 이상인 열은 목록 속성(`[]`)과 "빈 행 n개", "행 순서" 안내를 단다.
7. **노트 속성**: 필드마다 속성 하나, `hanmark-form`(양식 위키링크 또는 `builtin:gian`), `hanmark-form-hash`(SHA-256). Obsidian 예약 속성(tags·aliases·cssclasses·publish 등)과 두 관리 속성은 채울 값으로 쓰지 않는다. 본문은 작성 방법, 칸별 안내(형식·필수·목록), 주민등록번호 형식 칸이 있으면 개인정보 주의 콜아웃을 둔다.
8. **채워 저장**: 속성 값(글·숫자·목록) → `fillHwpx` → `validateHwpx`(실패하면 저장하지 않음) → `finalizeHwpxPackage`(같은 값이면 같은 바이트). 결과는 노트 옆 새 파일 `{양식명} (작성).hwpx`(이미 있으면 번호)이며 양식 원본은 바뀌지 않는다. 보고서에 채운 칸, 못 찾은 속성, 행이 모자라 들어가지 못한 목록 값(Kordoc이 조용히 버리는 것), 엔진 경고를 싣는다.
9. **양식 변경**: 저장된 해시와 양식 해시가 다르면 칸을 다시 읽어 새 칸만 속성에 더하고 기존 값은 그대로 둔다(보고서에 추가된 칸 이름).
10. **범위와 진입점**: HWPX만 채운다. HWP 양식은 "한글에서 HWPX로 저장 후 사용"으로 안내한다. 볼트 밖 양식은 Obsidian 첨부 규칙(`getAvailablePathForAttachment`)으로 볼트에 복사하고 알린다. 명령(두 문서 비교, 양식 입력 노트 만들기, 표준 기안문으로 입력 노트 만들기, 양식 채워 저장), 파일 메뉴(다른 문서와 비교, 양식 입력 노트 만들기), 한글 파일 보기 화면 버튼.
11. **내장 표준 기안문**: 일반기안문·간이기안문(별지 제1·2호서식, rhwp forms MIT)을 `gen-form-templates.mjs`가 base64로 내장한다(13.8KB). 실행 중 파일 시스템 경로를 쓰지 않는다.

## 6. 대안과 기각 사유

| 대안 | 장점 | 위험/기각 사유 | 재검토 조건 |
|---|---|---|---|
| Kordoc `compare` 그대로 | 코드 없음 | 조문 삽입 시 연쇄 오정렬(재현) | Kordoc 정렬이 동일 블록을 우선하면 보완 제거 |
| 유사도 가중 정렬을 직접 구현 | 고정점 사이도 최적 | 코드·계산량 증가, 고정점 방식으로 재현 사례 해결 | 고정점 사이 오정렬 사례가 보고될 때 |
| 글자 단위 강조 | 표시가 좁음 | `**(목적)**의` 같은 강조 깨짐, 읽기 어려움 | 없음 |
| `<u>` 밑줄 표시 | 신구조문대비표 관례 | Kordoc HWPX 생성기가 밑줄을 버림(실측) | Kordoc이 밑줄을 생성할 때 선택지로 추가 |
| 양식 원본에 바로 채우기 | 파일 하나 | 원본 불변 계약 위반 | 없음 |
| 머리행 표를 Kordoc 읽기 그대로 | 코드 없음 | "번호=성명" 같은 잘못된 속성 | Kordoc 양식 읽기가 머리행 표를 지원할 때 |

## 7. 한계와 미해결 질문

- 고정점 사이의 짝짓기는 Kordoc 유사도 규칙을 따른다. 고정점 없이 전부 고친 문서는 Kordoc 정렬과 같다.
- 표는 같은 위치의 셀끼리 비교하므로 행을 넣거나 빼면 아래 셀이 모두 바뀐 것으로 나온다.
- 머리행 표 판정은 추정이다. 틀리면 노트 속성을 고쳐 쓸 수 있고, 못 찾은 속성은 보고서에 나온다.
- 한컴오피스에서의 실제 표시(채운 값 인쇄, 대조표 HWPX)는 수동 E2E 5·6으로 확인해야 한다.
