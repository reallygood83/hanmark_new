# R-027 — 공문서 양식 사이의 Markdown·링크 일관성과 틀 높이 맞춤

- 상태: REQUIRED (자동 검증 CONFIRMED, Obsidian·한컴 실기 E2E 미완료)
- 작성일: 2026-09-30
- 최종 갱신: 2026-09-30
- 기준 버전/커밋: 작업 브랜치 `2.7.0`, Kordoc 4.15.7
- 관련 문서: R-018(엔진 이식), R-022(공문서 계약), R-024(제목·본문 매핑, 한림대 서식), R-025(8종 구별), R-026(양식 목록·미리보기)
- 담당 범위: `src/io/markdownAdapter.ts`(주석, 링크 글 대괄호), `src/io/gongmunOutline.ts`(틀 안 평문, 굵은 소제목, 요약 상자, 인용 나누기), `src/io/kordocEngine.ts`(경고 묶기, 틀 맞춤 연결), `src/io/hwpxFinish.ts`(틀 맞춤)

## 1. 조사 질문

4차 실기 피드백은 "마크다운 문법이나 링크가 양식마다 처리됐다 안 됐다 하고, 표가 넘치는 양식과 잘 나오는 양식이 들쭉날쭉하다"였다. 같은 노트를 10개 양식으로 만들 때 왜 결과가 다르고, 어떻게 한 규칙으로 맞추는가?

## 2. 범위

### 포함

- 인라인 Markdown(링크·굵게·코드·주석)이 양식마다 다르게 찍히는 문제
- Kordoc이 직접 그리는 틀의 넘침: 표지·제목 상자, 장 띠, 절 띠, 소제목 상자, 항목 띠, 목차, 기안문 두문, 계획서 표지 문서정보 표
- Kordoc 경고의 반복

### 제외

- 본문 Markdown 표와 차트. 행 높이는 Kordoc이 정한다. 시험 노트에도 Markdown 표가 없었다.
- PC 글꼴 자체의 폭 차이
- Kordoc 원본 수정. 상위 제보 후보로 남긴다.

## 3. 조사 방법과 증거

사용자 시험 파일 4개는 양식만 판별했다(개조식, 일송 회의록, AICR 보고서, 업무보고). 내용은 저장소에 복사하지 않았다. 시험 노트는 뉴스 목록 노트다. 제목 속 링크, 링크 글 속 대괄호, 목록이 든 콜아웃, HTML 주석, 중첩 목록이 들어 있다.

| 증거 | 유형 | 재현 또는 위치 | 신뢰도/한계 |
|---|---|---|---|
| 틀의 날것 출력 | 소스 | 업무보고의 띠·상자·목차, 보고서·계획서의 장 띠, 개조식 장 띠, 제목 상자는 글을 인라인 해석 없이 찍는다. Kordoc `plain`은 굵게·기울임·코드만 벗긴다. 그래서 `[제목](url)`이 그대로 보였다 | 높음 |
| 링크 글 속 대괄호 | 소스 | Kordoc 링크 규칙은 링크 글에 `]`를 허용하지 않는다. `[[AIC 2026] 제목](url)`은 링크가 되지 않는다 | 높음 |
| 주석 | 사용자 파일 | `<!-- -->`, `%% %%`가 본문 글자로 남았다 | 높음 |
| 일송 굵은 소제목 | 재현 | `**[글](url)**`는 Kordoc이 굵게 안의 링크를 읽지 못해 `**`가 남는다 | 높음 |
| 보고서 요약 상자 | 소스 | 요약 상자는 글을 그대로 찍어 `**`가 남았다 | 높음 |
| 목록이 든 콜아웃 | 재현 | Kordoc은 인용 여러 줄을 ※ 한 줄로 이어 "※ 제목 - 가 - 나"가 된다 | 높음 |
| 경고 반복 | 재현 | 같은 종류 경고가 항목마다 나와 20번 반복됐다 | 높음 |
| 틀 높이 | 소스·렌더 | Kordoc은 틀 높이를 한 줄 기준으로 고정한다. 업무보고는 절 띠 2,340, 소제목 상자 2,410, 항목 띠 2,350이다. 목차는 항목마다 한 줄로 센다(최소 62,000). 보고서·계획서 장 띠는 2,600이고, 기안문 두문 제목 행도 한 줄 높이다. 긴 제목은 틀 밖으로 넘친다 | 높음 |
| 계획서 표지 문서정보 표 | 소스·렌더 | 12pt 굵은 "문서번호"(약 17mm)에 칸이 약 15mm다. 모든 계획서에서 이름이 두 줄로 꺾여 칸을 넘친다 | 높음 |
| 틀 표 번호 | 소스 | Kordoc이 직접 그리는 표의 id는 개조식 틀 9,200,000부터, 나머지 틀 9,300,000부터다. Markdown 표는 1,000부터, 차트는 9,100,000부터다 | 높음(4.15.7 고정) |
| 한컴 동작 | 추론 | 한컴은 넘치는 셀의 행을 늘려 그릴 수 있다(미확인). HanMark 미리보기(Kordoc 렌더러)와 다른 뷰어는 파일에 적힌 높이를 쓴다 | 중간 |

## 4. 결정(구현됨)

1. **어댑터**
	- 코드 밖 주석을 지운다. 주석만 있던 줄은 없애고, 주석 자리의 겹친 빈칸은 한 칸으로 줄인다.
	- 링크 글 속 대괄호를 이스케이프해 링크 전체가 살게 한다.
2. **개요(제목·인용)**
	- 틀이 글을 그대로 찍는 제목은 평문으로 바꾼다(링크 글만 남기고 굵게·코드 표시를 뺀다). 대상은 업무보고의 모든 제목, 개조식과 띠 모양 보고서·계획서의 장 제목, 문서 제목이다.
	- 굵은 소제목(일송)은 링크 글 안쪽을 굵게 한다: `[**글**](url)`.
	- 보고서·계획서 요약 상자는 평문으로 찍는다.
	- 그 밖의 인용은 줄마다 ※ 하나로 나누고, 줄 앞 목록 표시를 뺀다. 요약 상자, 업무보고, 보도자료는 줄을 그대로 둔다.
3. **경고**: 같은 종류의 Kordoc 경고는 한 줄로 묶고 개수를 붙인다.
4. **틀 맞춤**(마감의 마지막 단계, 모든 공문서 양식)
	- 대상은 Kordoc이 직접 그린 표(id 9,200,000–9,399,999)다. 요약 상자(Kordoc이 이미 줄 수로 잰다)와 병합 셀이 걸친 행은 제외한다.
	- 줄 수는 Kordoc과 같은 줄바꿈 계산으로 센다(`simulateWrap`, `faceClassForGen`의 글꼴 폭 표).
	- 넘치지 않으면 그대로 둔다. 개조식 표지 제목처럼 두 줄을 담도록 만든 틀이 그렇다.
	- 넘치면 조금 넘치는 줄은 장평 95·90·85%로 줄여 한 줄에 넣는다(폭 2% 여유). 나머지는 줄을 바꾸고 행 높이를 늘린다. 행의 모든 칸과 표 높이를 함께 늘리고, 틀이 원래 글 아래에 두던 여백(최대 3,000)은 그대로 둔다.
	- 이름·값 2열 표에서 이름이 한 줄에 들어가지 않으면 이름 열을 넓히고 값 열을 줄인다. 값의 줄 수가 그대로일 때만 한다.
5. 사용자 노트로 10개 양식을 만들면 업무보고(틀 10곳)와 계획서(표지 문서정보 표)만 바뀐다. 나머지 8개 양식의 결과는 바이트까지 같다.

## 5. 대안과 기각 사유

| 대안 | 장점 | 위험/기각 사유 | 재검토 조건 |
|---|---|---|---|
| Kordoc 원본 수정(빌드 치환) | 근본 해결 | 하드닝 매니페스트가 커지고 엔진을 올릴 때마다 다시 맞춰야 함 | 상위에서 고칠 때 |
| 긴 제목의 글자 크기를 한 줄이 될 때까지 줄임 | 틀 모양 유지 | 긴 제목은 읽을 수 없을 만큼 작아짐 | 없음 |
| 긴 제목을 말줄임 | 틀 유지 | 내용이 사라짐(제품 계약 4 위반) | 없음 |
| 모든 표에 맞춤 적용 | 단순 | Markdown 표의 행 높이를 Kordoc과 다르게 바꿀 위험 | 사용자 보고 시 |
| 넘친 틀을 경고만 | 변경 없음 | 결과물이 여전히 넘침 | 없음 |

## 6. 한계와 미해결 질문

- 줄 수는 Kordoc의 글꼴 폭 표로 센다. 한컴 실제 글꼴 폭과 조금 다르면 한 줄 차이가 날 수 있다. 한컴에서 확인해야 한다.
- Kordoc이 이미 글자를 줄이고도 넘친 장 띠는 줄인 글자 그대로 두 줄이 된다(원래 크기로 되돌리지 않는다). Kordoc 경고("…제목을 줄이세요")는 그대로 알린다.
- 틀 표 번호 범위는 Kordoc 4.15.7 기준이다. 엔진을 올리면 테스트가 확인한다.
- 병합 셀이 있는 표(기안문 결문의 결재 칸 등)는 맞추지 않는다.
- 본문 Markdown 표는 이번 범위 밖이다.

## 8. 검증 조건

- 자동 테스트 `tests/gongmunConsistency.test.ts`(11개)
	- 주석 제거와 코드 안 보존, 링크 글 대괄호
	- 틀 안 평문(업무보고·보고서·개조식·장 모양별), 굵은 소제목의 링크, 요약 상자 평문과 인용 나누기, 경고 묶기
	- 합성 틀: 행 늘림(칸·표 높이, 아래 여백), 장평 축소, 건드리지 않는 경우(Markdown 표, 여유 있는 틀, 병합 행, 맞춤 꺼짐)
	- 업무보고 실제 생성: 짧은 절 띠 2,340 유지, 긴 절 띠와 번호 칸·표 높이, 세 줄 소제목 상자, 장평으로 한 줄에 넣은 상자, 두 번 맞춰도 같음
	- 계획서 표지 이름 한 줄(표 폭 불변), 기안문 긴 제목 행
- 틀 맞춤을 끄면 틀 테스트 4개가 실패하는 것을 확인했다. 전체 417개 통과.
- 수동: 사용자 노트로 10개 양식을 렌더해 전후를 비교했다(업무보고 목차·절 띠·소제목 상자, 계획서 표지). 한컴 실기는 확인하지 못했다.
- 완료 기준: 자동 테스트 전부 통과. 한컴 표시는 릴리스 관문(체크리스트 3)에서 확인한다.
