# R-028 — 삶의 질 마감: 툴바·미리보기·상태 표시줄·내보내기와 모션

- 상태: REQUIRED
- 작성일: 2026-09-30
- 최종 갱신: 2026-09-30
- 기준 버전/커밋: 작업 브랜치 `2.7.0`, Kordoc 4.15.7
- 관련 문서: R-019(출력 언어), R-021(노트 조립), R-022(공문서 계약), R-026(양식 목록·미리보기), R-027(틀 맞춤)
- 담당 범위: `src/ui/ToolbarController.ts`, `src/ui/QuickHwpxPreviewView.ts`, `src/ui/DocxPreviewView.ts`, `src/ui/HanmarkExportModal.ts`, `src/ui/ImportModal.ts`, `src/io/kordocSave.ts`, `src/io/gongmunExport.ts`, `src/main.ts`, `styles.css`, 새 모듈(§7)

## 1. 조사 질문

4차 실기에서 공문서 10개 양식이 모두 바이트 동일·검증 통과로 확인되었다. 사용자는 다음 단계로 "작지만 있어 보이고 쓰기 편해지는 마감"을 요청했다.

- 툴바가 항상 떠 있다. 한글처럼 익숙하다는 반응도 있지만, 마크다운 미니멀 편집기에 익숙한 사람은 얇게 접어 두기를 원한다. 지금 있는 숨기기는 완전히 숨긴다.
- 노트가 없으면 툴바가 없다.
- 내보낸 파일 이름만으로는 어느 양식인지 알 수 없고, 여러 양식을 비교하려면 10번 내보내야 한다.
- 디자인 기준: cmds-achmage의 응답 대기 테두리처럼, 애플식으로 미려하면서 절대 방해하지 않는 감각.

툴바·미리보기·상태 표시줄·내보내기에서 어떤 마감을, 어떤 계약으로 넣는가?

## 2. 범위

### 포함(18종)

- 툴바: 얇게 접기·엿보기, 좁은 창 한 줄과 ⋯, 분할 창 출렁임 제거, 지금 모양 표시, 글자 모양 단추, 색 기억, 표 격자, 빈 탭 시작 화면, 읽기 모드 서식 줄 접기, 미니멀 모양
- 미리보기: 다시 그릴 때 깜빡임·튐 제거, 쪽 번호·확대, 편집 위치 따라가기
- 상태 표시줄: 한국어 글자 수(공백 포함·제외, 원고지), 현재 양식
- 내보내기: 파일 이름에 양식, 여러 양식 한 번에, 노트별 마지막 양식 기억
- 공통: 모션·마감 토대(기다리는 순간의 빛 고리, 흐르는 선, 등장, 완료)

### 제외

- HWPX 내용 변화(바이트 동일 유지), 첫 실행 안내, 설정 화면 재구성

## 4. 결정

### 모션과 마감

1. 움직임은 사용자가 무언가를 기다리는 순간에만 쓴다. 평소 화면에는 반복 애니메이션이 없다.
2. 기다림은 2px 빛 고리(`@property --hanmark-orbit-angle` + `conic-gradient` + 마스크, 1.8초)와 흐르는 선(`transform`만 움직임)으로 보인다. 대상: 내보내기 창 주 버튼, DOCX 미리보기 상태 알약, 불러오기 진행 막대, HWPX 미리보기 상태 칩과 머리글 선, 여러 양식 내보내기의 지금 줄, 사용자가 시작한 작업 동안의 툴바 아래 선(`JobTracker`).
3. 결과는 160ms 동안 살짝 떠오르고, 끝나면 CSS로 그린 체크를 붙인다. 움직임 줄이기에서는 모든 애니메이션을 끄고 기다림은 고정 테두리로 남기며, 고대비 모드에서는 외곽선을 쓴다.
4. 토큰은 `body`에 둔다(Obsidian의 강조색이 `body`에 있다). 두 번째 강조색은 `--interactive-accent-hover`가 없는 테마를 위해 `--interactive-accent`로 대체한다.

### 툴바

5. 보이고 미뤄지지 않은 마크다운 창마다 툴바를 하나씩 둔다. 현재 노트의 툴바만 선명하고 나머지는 흐리게 쉰다. 흐린 툴바를 누르면 그 창을 먼저 활성화한다. 창을 바꿔도 노트가 움직이지 않는다.
6. 접기는 완전 숨김이 아니라 5~6px 띠와 손잡이다. 띠·손잡이·빈 곳 두 번 클릭·명령 `toggle-toolbar-collapse`로 접고 펴며, 접힌 줄은 `inert`다. 엿보기(기본 끔)는 띠에 머물면 줄들을 겹쳐 띄워 레이아웃을 바꾸지 않는다.
7. 줄은 늘 한 줄이다. 우선순위가 낮은 묶음부터 ⋯ 메뉴로 옮기고, 메뉴는 묶음별 제목을 달며, 메뉴 단추는 같은 자리에 두 번째 메뉴를 연다(하위 메뉴 API가 없다).
8. 커서의 문단 모양과 글자 모양(굵게·기울임 등, 코드·수식 우선)을 보인다. 활동 허브(`EditorView.updateListener` 하나)가 해당 창의 툴바에만 알린다. `@codemirror/view`는 Obsidian이 싣는 6.38.6으로 정확히 고정하고 번들에서 제외한다.
9. 글자색·형광색은 마지막 색을 기억한다(본체는 바로 적용, ▾는 고르기). 표는 8×8 격자로 넣는다. `insert-table` 명령과 같은 순수 함수를 쓰며 3×3 출력은 예전과 바이트 동일하다.
10. 읽기 모드에서는 서식 줄을 접는다(기본 켬). 모드 전환이 이벤트를 내지 않을 수 있어 창별 `MutationObserver`로 본다. 미니멀 모양은 테마 배경과 테두리 없는 단추를 쓴다.

### 미리보기

11. HWPX 미리보기는 보여 준 그림과 키가 같으면 다시 그리지 않는다. 새 그림은 떨어진 곳에서 만들어 `replaceChildren`로 한 번에 바꾸고, 같은 노트·같은 모드면 읽던 자리(쪽 + 쪽 안 비율)와 열어 둔 접기 칸을 되살린다. 로딩 상자는 첫 그림에만 쓴다. 다시 그리기에 실패하면 이전 그림을 두고 머리글에 알림을 띄운다.
12. 탐색 줄: ◀ `n / 전체쪽` ▶, − 폭 맞춤 +(50~200%), 따라가기, 상태 칩. 확대는 창 상태(`getState`)에 둔다. 쪽 위치는 SVG의 `g[data-page]`에서 읽는다.
13. 따라가기(설정 `previewFollowCursor`, 기본 켬): 노트의 제목(머리말·코드·수식·주석 제외)을 렌더 문단과 뒤에서부터 맞춘다. 번호·글머리(Ⅰ., 1), (가), □, ①, 제1장)를 허용하고 표 칸 문단도 본다. 맞춘 제목 사이는 줄 번호로 보간한다. 목표가 편안한 영역(12~72%) 밖일 때만 부드럽게 옮기고, 사용자가 미리보기를 휠·클릭·키로 움직이면 1.5초 멈춘다.
14. DOCX 미리보기: 두 교체 지점에서 스크롤 비율을 되살리고(맞춤 계산 다음 프레임), 수동 확대 중에는 자동 맞춤을 멈추며(`data-fit` 67·110~200 추가), 실제 DOCX 렌더에서만 쪽 이동을 보인다. 따라가기는 줄 비율로 한다. Word PDF 모드는 자체 쪽·확대가 있어 숨긴다.

### 상태 표시줄과 빈 탭

15. 글자 수: 머리말·주석·서식 기호·링크 주소·임베드·HTML 태그·각주 참조·표 구분 줄을 뺀 글자를 공백 포함·제외로 세고 200자 원고지 매수를 보인다. 선택이 있으면 선택만 센다. 편집 뒤에만 다시 세고 커서만 움직이면 앞의 값을 쓴다.
16. 양식 항목은 공문서 맥락(기억한 양식, `공문_종류` 속성, 양식 모드 미리보기)이 있을 때만 보인다. 누르거나 Enter로 메뉴를 열어 바꾸며, 바꾸면 노트에 기억한다.
17. 빈 탭(본 작업 영역·팝아웃, 사이드바 제외)에 문서 불러오기·새 노트·최근 내보낸 파일(볼트에 아직 있는 파일만, HWPX는 한글 파일 보기, DOCX·HTML은 파일 관리자)을 보인다. 목록이 같으면 다시 만들지 않고, 설정으로 끄거나 언로드하면 지운다.

### 내보내기

18. 공문서 파일 이름: 볼트 `{노트} - {양식}.hwpx`(겹치면 ` (n)`, 형제 파일과 대소문자 무시 비교), HWP에서 불러온 노트는 `{원본}_{양식}_{시각}.hwpx`. 양식 이름은 노트의 출력 언어를 따른다(R-019). R-026 §7 "파일 이름 불변"을 대체한다.
19. 여러 양식 내보내기: 노트를 한 번 스냅샷하고 양식을 명시해 늘 노트 옆 볼트에 저장한다(불러온 노트도, 저장 창이 끼어들지 않게). 그림이 없으면 한 번만 묻고 그 답을 모든 양식에 쓴다. 한 양식이 실패해도 나머지는 계속하고, 멈춤은 양식 사이에서 받는다. 전역·노트별 양식은 바꾸지 않는다.
20. 노트별 마지막 양식은 설정(`gongmunFormByNote`, 최대 500)에 두고, 이름 바꾸기·이동·삭제를 따라간다. 기억한 양식이 목록에 있으면 먼저 쓴다. 미리보기 계획에 양식을 명시해, 목록과 다른 전역 양식으로 그리던 버그를 고쳤다.
21. 최근 내보낸 파일(`recentExports`, 8개)은 HanMark가 볼트에 쓴 HWPX·DOCX·HTML만 기록한다.

## 5. 대안과 기각 사유

| 대안 | 장점 | 기각 사유 | 다시 볼 조건 |
|---|---|---|---|
| 양식 이름을 화면 언어로 | PC 언어와 일치 | 같은 노트가 PC마다 다른 이름이 된다(R-019 결정성) | 사용자가 파일 이름 언어를 따로 원할 때 |
| 여러 양식을 저장 창으로 하나씩 | 위치를 매번 고름 | 10번 끼어드는 창, 비교 목적에 맞지 않음 | 볼트 밖 저장 요구 |
| 노트별 양식을 노트 속성에 기록 | 노트와 함께 이동 | 사용자 노트를 조용히 바꾼다 | 사용자가 속성 쓰기를 명시적으로 켤 때 |
| 미리보기 DOM을 부분 갱신(diff) | 바뀐 곳만 교체 | SVG가 통째로 새로 나오며 복잡도에 비해 이득이 작다 | 초대형 문서에서 교체 비용이 문제일 때 |
| 따라가기를 원본 위치 표로 | 정확 | Kordoc SVG에 원본 줄 정보가 없다 | Kordoc이 원본 위치를 낼 때 |
| 툴바 완전 숨기기만 유지 | 단순 | 다시 찾기 어렵고 노트가 크게 튄다 | 없음 |
| 좁은 창에서 줄 바꿈 허용 | 모든 단추가 보임 | 높이가 바뀌어 노트가 흔들린다 | 없음 |
| 선택 변경을 `selectionchange`로 | CodeMirror 의존 없음 | 창별·팝아웃별 관리가 필요하고 어느 편집기인지 알기 어렵다 | `@codemirror/view` 고정이 깨질 때(대체 경로) |

## 6. 한계와 미해결 질문

- 빈 탭 화면(`.empty-state-container`)과 읽기 모드 전환은 Obsidian 내부 표시에 기대므로 버전에 따라 바뀔 수 있다. 자리가 없으면 `.view-content`에 붙이고, 둘 다 없으면 건너뛴다. 실기 확인 항목이다.
- 따라가기는 제목에 기대므로 제목 없는 긴 노트는 줄 비율로만 따라간다. 같은 제목이 여러 번이면 뒤에서부터 맞추고, 문서가 붙이는 제목이나 임베드 제목과 우연히 같으면 어긋날 수 있다.
- 글자 수는 한컴오피스 값과 다를 수 있다(각주·표 테두리·자동 번호를 세는 방식). 원고지 매수는 200자 단순 나눗셈이다.
- 브라우저 하네스는 Obsidian 호스트 기능을 대신하므로, 분할·팝아웃·실제 테마·키보드 흐름은 수동 점검 목록으로 확인한다.
- 번들은 4,260,496바이트로 상한 4,305,000바이트까지 약 44KB 남았다.
