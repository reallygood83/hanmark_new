# R-029 — 기관 공문 템플릿으로 기안하기

- 상태: PROPOSED
- 작성일: 2026-10-06
- 최종 갱신: 2026-10-06
- 기준 버전/커밋: 작업 트리 HanMark 2.7.0, Kordoc 4.15.7, 설정 v12. 버전 번호는 커밋 SHA를 이 문서에 고정하지 않았다.
- 관련 문서: [PRD](../prd/company-template.md), [스펙](../spec/company-template.md), [개발 계획](../plans/company-template.md), R-020, R-022, R-023, R-026, R-028
- 담당 범위: 기관 템플릿 명령, 노트별 템플릿 연결, 문서 스타일 자동 채우기, 공문 미리보기가 열린 기안

## 1. 조사 질문

기관마다 다른 기존 공문을 템플릿으로 등록하고, 그 양식이 열린 상태에서 기안한 뒤 HWPX로 저장하는 흐름을, 새 엔진이나 외부 API 없이 2.7.0 기능 위에 올릴 수 있는가?

## 2. 범위

### 포함

- 회사 템플릿 만들기, 이 노트를 템플릿으로 등록, 이 템플릿으로 새 문서
- HWPX의 이름 있는 바탕글·제목 스타일을 그 노트의 문서 스타일로 채우기
- 그 값으로 공문 양식의 본문 글꼴·크기·줄 간격을 채우기
- 템플릿 노트와 작업 노트를 분리
- 노트별 적용. 전역 활성 템플릿은 유지

### 제외

- 표지, 결재칸, 머리글, 바닥글, 글상자, 그림 배치의 복제
- 도장 날인. 직인 그림은 본문 그림
- `.hwp` 생성, HWP 양식 채우기, OCR
- 외부 API, 계정, AI 호출
- PDF·DOCX에서 문서 스타일 자동 추출
- 2.6.1 내보내기 창에 대한 소급

## 3. 조사 방법과 증거

| 증거 | 유형 | 재현 또는 위치 | 신뢰도/한계 |
|---|---|---|---|
| 문서 스타일 추출 | 소스 | `extractDocumentStyleProfile`: header.xml의 `바탕글`/`Normal`, `제목 1`–`6`/`Heading 1`–`6`. 바탕글이 없으면 charPr·paraPr ID `0` | 높음. 일부 글자에만 입힌 모양은 읽지 않음 |
| 스타일 가져오기 | 소스 | `importDocumentStyle`가 프로필과 `hwpxToProfile` 표를 템플릿 기록으로 저장 | 높음. 이 경로는 전역 활성 템플릿을 바꾼다 |
| 공문 양식 필드 | 소스 | `GongmunStyleOptions`: 본문 8–24pt, 줄 간격 100–250%, 여백 5–60mm | 높음 |
| 여백 상수 | 소스 | `DocumentStyleModal`의 `HU_PER_MM = 283.4646` | 높음. 공문 여백 자동 변환은 아직 없음 |
| 양식 하나 | 소스 | R-026 `listGongmunForms`. 내 양식은 종류와 모양을 함께 저장 | 높음 |
| 미리보기 유지 | 소스 | R-028. 미리보기가 열린 채 다시 그리고, 양식 전환과 HWPX 저장이 있음 | 높음. 기관 템플릿 노트와는 연결되어 있지 않음 |
| 도장 제외 | 소스 | R-022, R-023 제외 항목에 도장 날인 | 높음 |
| 2.6.1 화면 | 사용자 관찰 | 2026-10-06 내보내기 창 캡처. 문구가 Kordoc 4.2.5이고 공문서 종류만 있음. `새 양식 만들기` 없음 | 높음. 설치본 버전이며 작업 트리 2.7.0과 다름 |
| 문서 스타일 화면 | 사용자 관찰 | 2026-10-06 `HanMark 문서 스타일 편집`. 본문 한글 글꼴, 영문 글꼴, 크기, 굵기, 정렬, 줄 간격 | 높음. 템플릿 적용이 이 칸을 채우는지와는 별개 |

## 4. 확인된 사실

- 2.7.0은 HWPX에서 문서 스타일 프로필을 읽고, 공문 내 양식을 저장하고, 양식별 미리보기를 연 채로 둘 수 있다. 세 기능은 한 명령으로 연결되어 있지 않다.
- `importDocumentStyle`은 가져온 스타일을 전역 활성 템플릿으로 전환한다. 노트별 문서 스타일 연결은 없다.
- 공문서 생성은 `.hwpx`를 만든다. `.hwp` 저장 경로는 없다.
- 그림은 PNG, JPEG, GIF, BMP를 HWPX `BinData`에 넣는다. 직인을 결재란 좌표에 합성하는 코드는 없다.
- 불러오기, 공문 생성, 양식 채우기, 미리보기는 사용자 파일을 외부 API로 보내지 않는다. 네트워크는 노트에 적힌 원격 그림과, 사용자가 고른 이미지 업로드에만 쓰인다.
- 설정 스키마는 v12다. 다음 연구 번호는 이 문서를 등록하기 전 R-029였다.

## 5. 해석과 제안

PRD와 스펙이 제안하는 제품 계약이다. 구현이 끝나기 전에는 CONFIRMED가 아니다.

- 기관 템플릿은 템플릿 노트, 문서 스타일 기록, 공문 양식 기록의 묶음이다.
- 기안은 템플릿 노트의 복사본에서 한다. 미리보기는 그 공문 양식으로 연다.
- 문서 스타일 편집 화면은 적용 뒤에 이미 채워져 있다.
- 적용은 그 노트로 한정한다.
- 외부 API와 AI 호출은 두지 않는다. 노트에 이미 있는 마크다운을 내보낸다.

## 6. 대안과 기각 사유

| 대안 | 장점 | 위험/기각 사유 | 재검토 조건 |
|---|---|---|---|
| 전역 활성 템플릿만 전환 | 새 저장 구조가 없음 | 다른 노트의 빠른 HWPX가 바뀜 | 사용자가 전역 적용을 명시할 때 |
| 템플릿 노트에서 바로 기안 | 복사가 없음 | 기안이 기관 원본 양식을 고침 | 없음 |
| 올린 HWPX를 그대로 템플릿 패키지로 저장 | 표지와 직인 위치가 남음 | 2.7.0 스타일 모델이 그 배치를 읽지 못함. 양식 채워 저장과 중복 | Kordoc이 표지·결재칸을 구조로 내보내면 새 R 문서 |
| 문서 종류를 자동 확정 | 등록이 짧아짐 | 오분류가 다른 공문 틀로 저장됨 | 종류 분류의 재현 집합이 있을 때 |
| 외부 AI로 양식 해석 | 비정형 문서를 읽을 수 있음 | API, 문서 반출, 오프라인 계약과 충돌 | 제품 책임자가 반출을 허용할 때 |

## 7. 한계와 미해결 질문

- 버전 번호는 정하지 않았다.
- 한컴오피스에서 바탕글과 제목이 추출 값과 같은지는 구현 후 수동 확인이다.
- 여백의 HWP 단위 → 밀리미터 변환은 스펙의 상수와 범위 검사를 제안한 상태다. 구현 전 샘플로 한 번 대조한다.
- 2.6.1 설치본에서는 이 흐름을 확인할 수 없다.
