# 스펙 — 기관 공문 템플릿

- 상태: 제안
- 작성일: 2026-10-06
- 기준: HanMark 2.7.0, Kordoc 4.15.7, 설정 v12
- PRD: [company-template.md](../prd/company-template.md)
- 연구: [R-029](../research/R-029-company-template-workflow.md)

이 문서가 구현의 동작 계약이다. PRD의 성공 기준을 여기서 검사 가능한 규칙으로 적는다.

## 1. 용어

- **템플릿 노트**: 기관 양식의 원본 마크다운. 기안할 때 복사한다. 매일 고치는 문서가 아니다.
- **작업 노트**: 템플릿 노트의 복사본. 수신, 날짜, 본문을 여기서 고친다.
- **문서 스타일**: `DocumentStyleProfile`. 빠른 HWPX와 그 미리보기의 바탕글, 제목 1–6, 쪽 여백.
- **공문 양식**: `GongmunTemplateRecord`. 문서 종류와 기관 모양. 내 양식과 같은 저장소에 둔다.
- **기관 템플릿**: 템플릿 노트 경로, 문서 스타일 ID, 공문 양식 ID를 한 기록으로 묶은 것.

## 2. 기존 동작과의 경계

재사용한다.

- HWPX 본문 변환과 그림 첨부: 불러오기 실행기.
- 누름틀, 라벨 칸, 머리행 표의 속성 추출: 양식 채우기의 필드 읽기. 이번 흐름은 원본을 채우지 않는다.
- 바탕글·제목 스타일 추출: `extractDocumentStyleProfile`.
- 표 모양 추출: `hwpxToProfile`.
- 공문 미리보기, 미리보기에서 HWPX 저장, 노트별 양식 기억, 파일 이름 규칙.

새로 만든다.

- 세 명령과 그 화면.
- 기관 템플릿 기록과 노트별 연결.
- 템플릿 노트 복사.
- 문서 스타일 값으로 공문 양식의 본문 글꼴·크기·줄 간격을 채우는 순수 함수.
- 작업 노트를 내보낼 때 그 노트에 묶인 문서 스타일을 쓰는 경로. 전역 활성 템플릿은 그대로 둔다.

유지한다.

- 기존 명령 ID.
- 설정 v12를 읽는다. 새 키는 v13으로 올리고, 없는 키는 빈 기관 템플릿 목록이다.
- 원본 HWP, HWPX는 읽기만 한다.
- 같은 입력은 같은 HWPX 바이트. ZIP 항목 시각은 기존 고정 규칙을 따른다.
- 번들 상한 4,305,000바이트. 새 런타임 의존성은 두지 않는다.
- 화면 문구는 한국어와 영어 메시지 표에 같이 둔다.

## 3. 명령

| ID | 한국어 이름 | 언제 |
|---|---|---|
| `create-company-template` | 회사 템플릿 만들기 | 명령 팔레트, HWPX 템플릿 관리, 공문서 내보내기 창 |
| `register-company-template` | 이 노트를 템플릿으로 등록 | 템플릿 초안 노트가 활성일 때 |
| `new-document-from-company-template` | 이 템플릿으로 새 문서 | 등록된 템플릿이 하나 이상일 때. 템플릿 노트와 빈 탭에서도 연다 |

활성 노트가 마크다운이 아니면 등록과 적용은 이유를 알리고 끝낸다.

## 4. 회사 템플릿 만들기

1. 파일 선택기는 HWPX 하나를 받는다.
2. 확장자가 `hwp`이면 노트를 만들지 않고, 한컴에서 HWPX로 저장하라는 안내를 낸다.
3. PDF와 DOCX는 이 명령에서 받지 않는다. 본문만 필요할 때는 기존 불러오기를 쓴다.
4. 변환 옵션은 서식 문서 프리셋이다. 그림은 보관함 첨부로 저장하고 노트에 위키 링크로 남긴다. 암호 HWPX는 기존 불러오기와 같이 메모리 안에서만 암호를 묻고, 설정과 노트에 남기지 않는다.
5. 노트 위치는 현재 마크다운 노트의 폴더다. 열린 마크다운이 없으면 보관함 루트다. 파일 이름은 원본 이름에 `템플릿`을 붙이고, 겹치면 기존 내보내기 이름 규칙을 따른다.
6. 노트 본문은 변환된 마크다운이다. 머리말에는 변환기가 뽑은 필드가 있으면 그 속성을 넣는다. 기관 템플릿 초안 표시로 `hanmark-template-draft: true`를 넣는다. 이 키는 사람이 고치는 공문 속성이 아니다.
7. 같은 바이트로 `extractDocumentStyleProfile`과 `hwpxToProfile`을 실행한다.
8. 문서 스타일 기록은 만들되 전역 활성 템플릿으로 전환하지 않는다. 공문 양식 초안도 전역 활성 공문 양식으로 전환하지 않는다. 둘의 ID는 초안 노트의 기관 템플릿 임시 기록에만 연결한다.
9. 노트를 연다. 문서 스타일 편집을 이어서 열지는 않는다. 알림에 읽은 본문 글꼴, 크기, 줄 간격을 한 줄로 보여 준다.
10. 변환이나 스타일 추출이 실패하면 노트를 만들지 않는다. 이미 쓴 첨부가 있으면 그 실패를 알리고, 원본 파일은 그대로 둔다.

### 4.1 문서 스타일로 넣는 값

`extractDocumentStyleProfile`의 결과를 그대로 문서 스타일 프로필로 저장한다.

- 역할: `body`, `h1`–`h6`, 있으면 `quote`, `code`, `list`.
- 글자: 한글 글꼴, 영문·숫자 글꼴, 크기(pt), 굵기, 밑줄, 장평, 자간.
- 문단: 정렬, 줄 간격(%), 들여쓰기, 좌우 여백, 문단 앞뒤 간격, 다음 문단과 함께.
- 쪽: 추출된 `page`가 있으면 그대로.

이름 있는 스타일만 읽는다. 대응은 `바탕글`/`Normal`이 본문, `제목 N`/`Heading N`이 제목 N이다. 바탕글 스타일이 없으면 기존 함수와 같이 글자·문단 속성 ID `0`을 본문으로 쓴다. 글 일부에만 직접 입힌 모양은 넣지 않는다.

스타일 표시 이름은 원본 파일 이름에서 확장자를 뺀 문자열이다. 비어 있으면 `기관 템플릿`이다.

### 4.2 공문 양식 초안으로 넣는 값

문서 스타일 본문에서만 채운다. 범위 밖 값은 기관 서식 정규화가 버리므로 넣지 않는다.

- `fonts.body`: 본문 한글 글꼴.
- `fonts.heading`: 제목 1 한글 글꼴. 없으면 본문 글꼴.
- `bodyPt`: 본문 크기가 8 이상 24 이하일 때만.
- `lineSpacing`: 본문 줄 간격이 100 이상 250 이하일 때만.
- `bodyFont`: 글꼴 이름에 `고딕`이 있으면 `gothic`, `명조` 또는 `바탕`이 있으면 `myeongjo`. 둘 다 해당하면 `고딕`을 우선한다. 어느 쪽도 아니면 이 필드는 비운다.
- 쪽 여백: HWP 단위를 `DocumentStyleModal`의 `HU_PER_MM`(283.4646)로 나눠 밀리미터로 반올림한다. 위·아래·왼쪽·오른쪽이 모두 5 이상 60 이하일 때만 `margins`에 넣는다.

문서 종류, 기관명, 결재란, 띠 색, 표지는 초안에서 비운다. 표 프로필은 `hwpxToProfile`에 표가 있을 때만 `tableStyle`로 붙인다.

## 5. 등록

활성 노트가 템플릿 초안이거나, 아직 기관 템플릿에 연결되지 않은 마크다운일 때 등록할 수 있다.

등록 화면 필드:

- 이름. 기본값은 노트 제목 또는 파일 이름.
- 문서 종류. 8종이며 기본 선택은 `report`(보고서)다. 파일 이름이나 제목에 회의록, 기안, 계획, 통지, 보도, 업무보고가 있으면 그 종류를 기본 선택으로 보여 주고, 저장 전까지 확정하지 않는다.
- 기관명.
- 결재란. 쉼표로 구분하고 최대 8개.

저장 시:

1. 공문 양식 초안이 있으면 그 기록에 종류, 기관명, 결재란을 넣어 갱신한다. 없으면 그 값만 가진 내 양식을 만든다.
2. 문서 스타일 초안이 있으면 표시 이름을 등록 이름과 맞춘다.
3. 기관 템플릿 기록을 설정에 저장한다.
4. 노트 머리말에서 `hanmark-template-draft`를 지우고 `hanmark-company-template: true`를 넣는다.
5. 그 노트의 양식 기억은 이 공문 양식을 가리킨다.
6. 전역 활성 문서 템플릿과 전역 활성 공문 양식은 바꾸지 않는다.

등록 뒤 알림은 템플릿 이름을 말한다.

## 6. 새 문서

1. 등록된 기관 템플릿이 하나면 그것을 쓴다. 둘 이상이면 이름을 고른다.
2. 템플릿 노트를 읽는다. 노트가 없으면 등록이 깨졌다고 알리고 끝낸다.
3. 같은 폴더에 새 노트를 만든다. 이름은 템플릿 이름이다. 겹치면 번호를 붙인다.
4. 복사본은 본문과 공문 속성을 가져온다. `hanmark-company-template`와 `hanmark-template-draft`는 넣지 않는다.
5. 복사본의 노트별 연결은 같은 기관 템플릿 ID다. 양식 기억도 그 공문 양식이다.
6. 복사본을 열고 HWPX 미리보기를 공문 모드로 연다. 미리보기는 이 양식을 그린다.
7. 템플릿 노트 파일은 수정하지 않는다.

## 7. 열린 노트에 적용

작업 노트에서 기관 템플릿을 고르면 노트별 연결만 바꾼다. 본문과 기존 공문 속성 값은 유지한다. 템플릿에만 있고 노트에 없는 속성 키는 빈 값으로 더한다. 이미 있는 값은 덮어쓰지 않는다.

적용 뒤 문서 스타일 편집을 그 노트의 연결로 열면 4.1의 값이 칸에 채워져 있다. 이 화면에서 저장하면 그 기관 템플릿의 문서 스타일 기록만 갱신한다. 다른 기관 템플릿과 내장 템플릿은 그대로다.

## 8. 내보내기

작업 노트나 템플릿 노트를 HWPX로 저장할 때:

- 노트에 기관 템플릿이 연결되어 있으면 빠른 HWPX는 그 문서 스타일과 표 프로필을 쓴다.
- 공문서 HWPX는 그 공문 양식의 종류와 모양, 노트의 공문 속성을 쓴다. 양식에 종류가 있으면 그 종류가 노트의 `공문_종류`보다 앞선다. 이 우선순위는 2.7.0 내 양식과 같다.
- 연결이 없으면 2.7.0과 같다. 전역 활성 템플릿과 노트별 양식 기억을 쓴다.
- 그림은 기존 규칙대로 PNG, JPEG, GIF, BMP만 넣고, 실패한 그림은 알린다.
- 직인 위치 지정, 도장 합성, 발신명의 위 겹치기는 하지 않는다. `![[직인.png]]`는 본문 그림이다.
- 결과 파일은 `.hwpx`다.

미리보기는 내보내기와 같은 문서 스타일, 같은 공문 양식을 그린다.

## 9. 저장 형식

설정 v13에 다음을 더한다. v12 데이터는 그대로 읽고 빈 목록을 더한다.

```ts
interface CompanyTemplateRecord {
  id: string;
  name: string;
  notePath: string;
  documentStyleId?: string;
  gongmunTemplateId?: string;
  sourceName?: string;
  createdAt: string;
  updatedAt: string;
}
```

- 보관 위치: 템플릿 보관함 안의 `companyTemplates`.
- 노트별 연결: 기존 양식 기억과 같은 경로 맵 `companyTemplateByNote`. 노트 이름 변경과 이동은 `formMemory`의 경로 갱신을 같이 탄다.
- 삭제: 템플릿 노트를 지우면 다음 사용 때 없음을 알린다. 문서 스타일과 공문 양식 기록은 남긴다. 사용자가 템플릿 관리에서 기관 템플릿을 지우면 연결만 풀고, 이미 만든 작업 노트의 본문은 지우지 않는다.
- 머리말 키 `hanmark-company-template`와 `hanmark-template-draft`는 내보내기 본문에서 빠진다. 공문 생성기에 넘기지 않는다.

## 10. 화면 문구

새 문자열은 `src/i18n/ko.ts`와 `en.ts`에 같은 키로 넣는다. 명령 이름, 등록 화면, 빈 스타일, HWP 거부, 깨진 템플릿, 적용 완료를 포함한다. 문서 종류 이름은 기존 `gongmun.preset.*`를 재사용한다.

## 11. 실패

| 상황 | 동작 |
|---|---|
| HWP 선택 | 노트 없음. HWPX로 저장하라는 안내 |
| 암호 취소 또는 실패 | 노트 없음. 암호는 저장하지 않음 |
| HWPX에 header 또는 section이 없음 | 노트 없음. 스타일을 읽지 못했다는 안내 |
| 템플릿 노트 경로가 없음 | 새 문서와 내보내기 연결 실패. 본문 내보내기로 떨어지지 않고 알림 후 중단 |
| 그림 누락 | 기존 내보내기 그림 실패와 같음 |
| 등록 이름이 비어 있음 | 저장하지 않음 |

## 12. 수용 테스트

순수 테스트:

- 바탕글과 제목 1–3이 있는 HWPX에서 프로필의 글꼴, 크기, 줄 간격이 원본 스타일과 같다.
- 바탕글이 없으면 ID `0`이 본문이다.
- 본문 11pt, 160%, 휴먼명조는 공문 초안의 `bodyPt` 11, `lineSpacing` 160, `fonts.body` 휴먼명조, `bodyFont` `myeongjo`다.
- 본문 7pt는 `bodyPt`에 넣지 않는다. 줄 간격 90도 `lineSpacing`에 넣지 않는다.
- 여백 변환이 5–60mm 안이면 네 값을 넣고, 한 변이 범위를 벗어나면 `margins`를 넣지 않는다.
- 고딕이 이름에 있으면 `gothic`이 명조보다 우선한다.
- 등록 기록은 전역 활성 ID를 바꾸지 않는다.
- 복사 계획은 템플릿 플래그를 빼고 공문 속성은 유지한다.
- 적용은 기존 속성 값을 유지하고 없는 키만 빈 값으로 더한다.
- 연결이 없는 노트의 내보내기 옵션은 2.7.0 전역 선택과 같다.
- v12 설정은 v13에서 기관 템플릿 목록이 빈 상태다.

화면과 실기:

- 명령 세 개의 한국어·영어 이름이 팔레트에 있다.
- 샘플 HWPX로 초안 노트가 생기고, 문서 스타일 편집의 본문 칸이 그 파일 값이다.
- 등록 후 새 문서는 다른 파일이고, 템플릿 노트의 바이트는 그대로다.
- 새 문서의 미리보기가 고른 문서 종류로 열린다.
- 저장 파일이 `.hwpx`이고 한컴에서 바탕글과 제목 스타일을 확인할 수 있다.
- 네트워크를 끈 상태에서 위 과정이 된다.
- 기존 `npm run check`가 통과한다.

## 13. 완료로 보지 않는 것

- 한컴 화면과 미리보기가 픽셀 단위로 같다.
- 직인이 결재란 위에 찍힌다.
- PDF에서 문서 스타일이 자동으로 채워진다.
- 2.6.1 내보내기 창에 이 버튼이 있다. 구현 기준은 2.7.0 작업 트리다.
